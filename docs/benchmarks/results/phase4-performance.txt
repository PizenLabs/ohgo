Notes
-----
- The symbol benchmark builds the AST index once in setup, then measures the
  freshness walk, exact lookup, and declaration-range hash per completion.
- The path benchmark reads one named file; no index is built.
- The post-run check re-reads the same bounded target set and performs no
  model or tool execution.
- No contract/evidence bytes are added to the model context. The semantic
  assessor is deterministic and makes no provider call.
- Caps: 8 targets per contract, 256 files per package target, 4 MiB per file,
  16 MiB total read per capture/check.
- Phase 3 measured a cold 2,000-file / 62,000-symbol index build at
  181.998625ms. A symbol/package contract may trigger that existing index build
  before the run if the model has not used the symbols tool yet; it is the same
  index, not a second one.

Closure addendum
----------------
The final tree resolves a shell command's effective directory for verification
scope. This adds one path resolution and a small segment walk per bash call; it
does not change the contract/capture/completion microbenchmarks or the 23-case
aggregate. The closure rerun reproduced the same case states and metrics; only
timings varied. These are synthetic measurements, not production-scale claims.
